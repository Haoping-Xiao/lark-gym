# AutomationBench → OfficeGym

固定上游提交见 `automationbench.json`。该清单覆盖 600 道正式题和 200 道辅助题；只有实际通过检查的任务标记 `local-cli-verified`，容器检查单列。此实现是飞书业务改写，不是官方评测复现。

`inventory.py` 导出原始公开任务；`simple-crm.py` 和 `formal.py` 从逐题改写文件生成原生 Harbor 包。文件中参考解和评分信息只进入 solution/tests，不能进入 agent 镜像。原始导出文件从参数传入，不在仓库重复存储。重新生成后运行 Prettier。

- CRM、项目、客服、订阅者和内容排期改为飞书多维表格业务台账，collection 区分实体；邮件与群通知改为飞书私聊和群消息。原始邮件内容及政策保留原文，指令用中文。
- 外部平台排期任务只登记排期，不实际发布。视频会议改为带视频配置的飞书日历日程；3186 合并原来两个平台的创建操作，但同时检查日历与视频配置。
- 3150 的 webinar 注册改为报名台账和仅参会人可加入的会议，不声称复现完整 webinar 服务。
- 3184 上游要求更新 rec_005，但初态缺少该实体；补充 In Progress 的项目记录，再评分更新结果。
- 3187 上游未提供支持经理身份；改写明确使用 @Support Manager 文本提醒，不声称触发真实成员 mention。
- 3191 按用户题意通知名单全部五人，修补上游仅检查两人的遗漏。原题没有提供每周亮点，允许明确报告无可核实进展。
- 部分题将自由摘要明确改为保存原文，以避免给中文摘要强加不可见的英文精确匹配。通知中的名称、金额、ID、日期和明确规定的标题保留字面值。
- 原题未明确的日程时区使用 UTC 并写入指令；未指定时长使用 60 分钟。内容排期的上午/默认、中午、下午分别为 09:00、12:00、15:00 UTC。
- 评分增加无关状态保护及多余通知拒绝。正式题保留原噪声和政策材料、跨表查找及不应通知的对象；没有通过迁移的题仍为 pending。

本地检查不等于 Harbor 容器检查。参考解使用真实 Go CLI，经同一个有状态 Mock 执行；测试还检查空操作、缺少必要业务操作、无关数据误改。未知 API 返回 501 后将轨迹判为环境覆盖不足，而不是 agent 失败。
