# Lark 原生业务迁移

2026-09-30 用户要求所有邮件使用 Lark Mail，其他业务也必须合理承接于 Lark 原生能力。此前审计结束不代表本次迁移完成。

## 当前范围

全量审计覆盖 800 题。原邮件来源清单包含 553 题，另有 7 题没有来源 Gmail 数据但需要发信；全部 560 题现使用原生 Lark Mail。文档和云盘进一步迁移为真实 Docs／Drive 操作；社媒、签署和导出等不能由 Lark 执行的外部动作，明确承接为内部队列或请求，不伪称外部执行成功。最终映射详见 native-surface-audit.json。

原邮件材料从 IM 会话移入 Lark Mail，参考解通过真实 CLI 读取。共保留 1724 封来源邮件，邮件正文和非邮件业务数据经过逐题一致性检查。来源编号编码为 CLI 接受的邮件 ID，原编号仍可从 SMTP Message-ID 追溯。93 个已读字段与标签冲突按原 Gmail 查询工具实际采用的 `is_read` 解释，适配证据保存在本地审计产物。未编造缺失日期；此类任务留待单独处理。

62 个真实 CLI 参考路径均通过程序评分，62 个额外发送未要求邮件的反例均被拒绝；61 个空操作被拒绝。sales-703 属于文本交付，空操作的程序层放行后仍需语义评分，不能将其记作空操作验收通过。本批没有新增模型玩家或语义裁判调用。

## 常规发信与已读状态：191 题

新增 189 题原生发信，保留 2438 封完整来源邮件；186 处已读字段冲突仍按原工具的 is_read 解释。各题真实 CLI 参考路径、空操作、额外邮件检查均符合预期；另有 378 个错收件人、漏发反例全部被拒绝。主题及正文原有含义、禁止内容仍交给独立语义评分，并保留原始约束与实际邮件作为证据。

回归测试改为按业务操作定位命令，不依赖原私聊步骤的位置；独立的 IM 路由测试使用固定专用初态。测试还发现重新生成的商机验证器漏掉既有的大小写宽容选项，已在模板和该题中恢复，相关正反例通过。本轮全仓 1291 项检查及 oracle 通过。上述证据是程序验证，没有新增玩家或语义裁判调用。
